`useRpcMutation(procedimiento, opciones?)` prepares a call to a data-changing `server/rpc` procedure. It does nothing until you call `mutate(input)`, never in SSR; it then sends the CSRF token like `rpc.*`, updates `pending`, `data` and `error` and returns the procedure's output, or rejects with its error. It is the write counterpart to [`useRpcQuery`](/en/docs/reference/use-rpc-query), and the RPC counterpart to [`useApiMutation`](/en/docs/reference/use-api-mutation).

It is generated by the application's clients and auto-imported in `.meeko` files; call it at `<script>` top level.

## Usage

```html
<!-- app/components/RenameUser.meeko -->
<script lang="ts">
const props = defineProps<{ id: string; name: string }>();
const rename = useRpcMutation("users.rename");
const name = signal(props.name);
async function save(): Promise<void> {
  await rename.mutate({ id: props.id, name: name.value });
}
</script>

<template>
  <input model="name">
  <button type="button" bind:disabled="rename.pending.value" on:click="save">Guardar</button>
  <p if:when="rename.error.value" role="alert">{rename.error.value.message}</p>
</template>
```

## Parameters

| Parameter            | Type                           | Default  | Description                                                                                                     |
| -------------------- | ------------------------------ | -------- | --------------------------------------------------------------------------------------------------------------- |
| `procedimiento`      | procedure ID                   | required | Such as `"users.rename"`.                                                                                       |
| `opciones.retrySafe` | `{ key, storage? }`            | none     | Since `1.2`. Saves the intent with an idempotency key and retries it with the same key if there is no response. |
| `opciones.onSuccess` | `(output, attempt) => unknown` | none     | Since `1.2`. Once per successful attempt, including automatic retries.                                          |
| `opciones.onError`   | `(error, attempt) => unknown`  | none     | Since `1.2`. Once per failed attempt; `attempt.uncertain` indicates no response was received.                   |

## Return value

An `RpcMutation<Input, Output>`:

| Property        | Type                             | Description                                                                                                        |
| --------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `mutate(input)` | `Promise<Output>`                | Calls the procedure. Resolves with its output or rejects with its error (a `ClientError` if the server responded). |
| `pending`       | `ReadonlySignal<boolean>`        | `true` while a call is in progress.                                                                                |
| `data`          | `ReadonlySignal<Output \| null>` | Output of the last successful call, or `null`.                                                                     |
| `error`         | `ReadonlySignal<Error \| null>`  | Failure of the last call, or `null`.                                                                               |

With `retrySafe`, adds `uncertain`, `retry()` and `discard()` (`RetrySafeMutation`).

## Examples

### Write and read again

```html
<script lang="ts">
const props = defineProps<{ params: { id: string }; search: Record<string, string | string[]> }>();
const user = await useApi("/api/users/[id]", { params: { id: props.params.id } });
const rename = useRpcMutation("users.rename");
async function save(name: string): Promise<void> {
  await rename.mutate({ id: props.params.id, name });
  await user.refresh();
}
</script>
```

### Notifications for each attempt

```html
<script lang="ts">
const rename = useRpcMutation("users.rename", {
  onSuccess: (user) => notify(`Guardado como ${user.name}.`),
  onError: (error) => notify(isClientError(error) ? "El nombre no es válido." : "No se pudo conectar."),
});
</script>
```

`onSuccess` and `onError` are called after updating `data`, `error` and `pending`. The `mutate` promise still resolves or rejects as usual.

### A payment safe against retries

```html
<script lang="ts">
const charge = useRpcMutation("sales.checkout", { retrySafe: { key: "pos:sale" } });
const failure = signal("");
async function pay(input: SaleInput): Promise<void> {
  failure.value = "";
  try {
    await charge.mutate(input);
  } catch (error) {
    // Sin respuesta: queda en verificación y se reintentará con la misma clave.
    if (!charge.uncertain.value) failure.value = error instanceof Error ? error.message : String(error);
  }
}
function discard(): void {
  if (window.confirm("Descarta esta venta sólo si comprobaste que no se registró.")) charge.discard();
}
</script>

<template>
  <div role="alert" if:when="charge.uncertain.value">
    <p>Venta en verificación: se reintentará con la misma clave, así que no se cobrará dos veces.</p>
    <button bind:disabled="charge.pending.value" on:click="() => charge.retry().catch(() => {})">Reintentar ahora</button>
    <button on:click="discard">Descartar</button>
  </div>
  <p if:when="failure.value">{failure.value}</p>
</template>
```

## Common mistakes

### Await it with `await`

```ts bad
const rename = await useRpcMutation("users.rename");
```

`meeko check` reports `MEEK055: useRpcMutation no se puede esperar con await; llámalo sin await y espera su mutate(input) en un handler`.

<!-- no-check -->

```ts good
const rename = useRpcMutation("users.rename");
```

### Create it inside a function

```ts bad
async function save(): Promise<void> {
  await useRpcMutation("users.rename").mutate({ id: "1", name: "Ada" });
}
```

`meeko check` reports `MEEK054: useRpcMutation() debe llamarse en el nivel superior de <script>, no dentro de una función, un handler, un effect ni onMounted`.

<!-- no-check -->

```ts good
const rename = useRpcMutation("users.rename");
async function save(): Promise<void> { await rename.mutate({ id: "1", name: "Ada" }); }
```

### Input with another type

```ts bad
const save = () => rename.mutate({ id: 1, name: "Ada" });
```

`meeko check` reports `TS2322: Type 'number' is not assignable to type 'string'`: input is checked against the procedure's `input` schema.

<!-- no-check -->

```ts good
const save = () => rename.mutate({ id: String(user.id), name: "Ada" });
```

### An unhandled rejection

```html bad
<button on:click="() => rename.mutate({ id, name: name.value })">Guardar</button>
```

If the server responds with an error, the promise rejects; the handler delivers it to the nearest `provideErrorHandler` (source `"event"`) and `rename.error` reflects it. To handle the error there, catch it:

```html good
<button on:click="() => rename.mutate({ id, name: name.value }).catch(() => {})">Guardar</button>
<p if:when="rename.error.value" role="alert">No se pudo guardar.</p>
```

## Notes

- **Never in SSR.** The server and navigation dry runs never send a mutation; with `retrySafe`, they do not retry it either.
- **Consistent state.** Since `1.2`, each submission starts with `pending` set to `true` and `error` to `null` in a single update, and ends by writing `data` or `error` alongside `pending` set to `false`.
- **Security.** The call carries the session's CSRF token and `Origin`; the procedure applies its own guards. With `retrySafe`, input is saved in browser storage: do not include secrets.
- **`retrySafe`.** While an uncertain intent exists under the key, `mutate` rejects with `MUTATION_UNCERTAIN` without sending anything. The server receives the validated key in `context.idempotencyKey` and handles deduplication.
