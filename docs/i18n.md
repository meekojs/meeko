# Módulo i18n

El módulo integrado `@meekojs/meeko/i18n/module` carga los catálogos JSON necesarios antes del render SSR o de la hidratación. Vite emite un chunk por idioma y ámbito. Los mensajes se preparan al compilar; en ejecución sólo se resuelven argumentos y variantes. El módulo no necesita dependencias adicionales.

## Configuración

```ts
// meeko.config.ts
import { defineMeekoConfig } from "@meekojs/meeko/framework";

export default defineMeekoConfig({
  modules: [["@meekojs/meeko/i18n/module", {
    defaultLocale: "es",
    catalogs: {
      es: { common: "app/locales/es/common.json", home: "app/locales/es/home.json" },
      en: { common: "app/locales/en/common.json", home: "app/locales/en/home.json" },
    },
    routes: { "/es": ["home"], "/en": ["home"] },
  }]],
});
```

Las rutas del proyecto deben incluir el idioma, por ejemplo `app/pages/es/index.meeko` y `app/pages/en/index.meeko`, o usar un parámetro de ruta compartido. Este módulo **no crea rutas ni duplica páginas**. Una URL sin prefijo usa `defaultLocale`. El cambio entre idiomas usa una navegación completa; la navegación dentro del mismo idioma precarga el ámbito de la ruta y conserva el comportamiento habitual de Meeko. El módulo fija `<html lang>` y `dir` por petición, también en SSR concurrente.

`common` se carga en todas las rutas. `routes` usa los IDs exactos del manifiesto de Meeko para indicar otros ámbitos; una ruta sin entrada sólo carga `common`. Todos los idiomas deben tener los mismos ámbitos y las mismas claves dentro de cada ámbito. Para un proyecto pequeño, también se admite un único archivo por idioma (`catalogs: { es: "app/locales/es.json", en: "app/locales/en.json" }`).

## Catálogos

```json
{
  "home": {
    "greeting": "Hola, {name}!"
  },
  "files": {
    "plural": "total",
    "forms": {
      "=0": "No hay archivos",
      "one": "{total} archivo",
      "other": "{total} archivos"
    }
  },
  "role": {
    "select": "value",
    "forms": {
      "admin": "Administrador",
      "other": "Miembro"
    }
  }
}
```

Los catálogos del mismo ámbito deben tener las mismas claves en cada idioma. `other` es obligatorio en `plural` y `select`; las categorías plurales las determina `Intl.PluralRules` del idioma. Los argumentos admiten `{name}` y se insertan como texto; la plantilla `.meeko` los escapa al generar HTML. Esta sintaxis es un **subconjunto explícito**, no un parser completo de ICU MessageFormat: no admite plurales anidados, offsets ni esqueletos de formato. Para números y fechas se usa `Intl` mediante la API del módulo.

```html
<script lang="ts">
const i18n = useI18n(); // autoimport del módulo
</script>

<template>
  <h1>{i18n.t("home.greeting", { name: "Meeko" })}</h1>
  <p>{i18n.t("files", { total: 2 })}</p>
  <button on:click="() => i18n.switchLocale('en')">English</button>
</template>
```

`useI18n()` también expone `locale`, `number(value, options)` y `date(value, options)`. Los formateadores `Intl` se reutilizan por opciones dentro de cada petición o pestaña. Una clave ausente o un argumento obligatorio ausente produce un error visible durante desarrollo.

`meeko check`, `meeko dev` y `meeko build` generan `.meeko/types/i18n.d.ts` con las claves disponibles. La llamada a `t` comprueba esas claves en TypeScript; los valores de los argumentos se validan al ejecutar el mensaje.

## Alcance actual

El tipado de los argumentos de cada mensaje, `hreflang` y el prefijo automático de rutas son pasos posteriores. El caché de páginas debe distinguir las URL de cada idioma. No se debe usar el mismo URL para HTML de idiomas distintos sin configurar también las cabeceras de caché correspondientes.
