## Final type and error-boundary closure (2026-10-25)

- The stale-handle limitation in the preceding historical entry is resolved. New sessions carry an opaque `familyId`; memory, Redis and SQL rotate and revoke that family atomically, so an old handle invalidates the current ID after multiple rotations. Production stores must implement atomic `replace` and `revokeFamily`. The SQLite fixture includes the documented migration, Redis legacy rows migrate on first rotation, and real Redis 8.10.2 passed 2/2 with isolated prefixes, concurrency, TTL, expiry, revocation, replacement-client recovery and clean close.
- End-to-end types were tightened without runtime globals: exported overloads are deduplicated, reexported generic types preserve constraints and defaults through the resolved TypeScript symbol, and app/server/shared projects use `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess` and `verbatimModuleSyntax`. API, RPC and Socket reject Standard Schema contracts containing `any`, `unknown`, `never` or unresolved type parameters, including nested shapes, while recursive concrete contracts remain valid. The installed-tarball consumer imports `ComponentProps` from a `.meeko` page and proves invalid nested props fail TypeScript.
